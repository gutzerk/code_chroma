# Unread messages panel (Slack + Outlook)

A rail button with an unread badge opens a side panel over the canvas listing every unread Slack and Outlook message, newest first, in one flat list. Clicking an item opens it in Slack (`slack://` deep link; an "in browser" link carries the web permalink) or Outlook (`webLink`). Read-only: CodeChroma never replies, never marks anything read, and writes nothing to disk except the sign-in tokens. Plan and decisions: [`docs/planning/029-unread-messages.md`](../planning/029-unread-messages.md).

C# bridge only, like workflows; the Python bridge has no mirror (gap recorded in `docs/planning/012-csharp-bridge.md`). On a bridge without these routes (mock, Python bridge, no `VITE_ENGINE_BRIDGE_URL`) the first `GET /messages/unread` answers 404 or "no bridge", so the rail button hides and focus re-checks stop.

## Bridge (`dotnet/CodeChroma.Bridge/Messages/`)

```
Slack Socket Mode ──► SlackSource ─┐
Graph poll (60 s) ──► OutlookSource┼─► UnreadFeed (in memory) ──► GET /messages/unread
                                   │                          └─► ws ping "messages-changed" ──► UnreadPanel
Keychain ◄── ITokenVault ──────────┘
```

- `UnreadFeed.cs`: `UnreadItem` (wire fields plus an in-memory `Group` = Slack conversation / Graph folder id) and the `IMessageSource` port (`RecheckAsync` full re-read, `RunAsync` background loop). The feed keeps one slot per source (`state` connected/disconnected/error, `error`, `synced_at`, items). `Replace`/`ReplaceWhere`/`Upsert`/`RemoveWhere` fire the `messages-changed` ping (no workspace key, so every tab gets it) only when items or state change, never for a bare `synced_at` bump. ⚠ `Fail` keeps the last good items: a failed poll shows an error note, it does not empty the list.
- `SlackSource.cs`: `SlackApi` (Bearer, `ok:false` → `SlackApiException`, 429 retried with `Retry-After` capped at 30 s). Full re-check = `auth.test` (cached identity), `users.conversations` (public, private, mpim, im; 200 per page, capped at 1000 conversations), then per conversation (4 in parallel) `conversations.info` → `last_read` and `conversations.history?oldest=last_read` (20 per conversation). A message counts when someone else wrote it, it has no subtype or one of `thread_broadcast`/`file_share`/`bot_message`/`me_message`, and it is not a thread reply. Socket Mode (`apps.connections.open` with the `xapp-` token) acks every envelope, upserts a new message, drops an item on `message_deleted`, and clears a conversation when the user writes a top-level message in it (Slack marks it read then; a thread reply does not). Slack sends no user event when a channel is read elsewhere, so `RunAsync` re-reads only the conversations that still hold items every 60 s (`SlackOpenRecheck`, the "disappears once read" bound) and does a full re-check every 15 min (`SlackFullRecheck`), at start, on every socket reconnect and on window focus. Re-checks run one at a time (`_recheckGate`). Each conversation's fresh read is published as it lands (`ReplaceWhere` scoped to that conversation), and items of conversations no longer listed are dropped first, so a large workspace fills progressively instead of after the last of up to 1000 reads; the next full re-check is scheduled 15 min after the previous one *finishes*. The socket starts before the first full re-check. ⚠ A refused app-level token (`_socketError`) is passed to every `ReplaceWhere`, so a re-check cannot flip the source back to connected while live updates are dead; a successful reconnect clears it and runs a full re-check. A conversation whose read failed with a non-auth Slack error (e.g. `ratelimited` after the retries) or that got a socket event while it was being read keeps its current items instead of being overwritten, so a large workspace still fills and a stale read never undoes a newer socket update; auth errors (`invalid_auth`, `token_revoked`, …) still fail the whole re-check. Previews flatten mrkdwn (`<url|label>`, `<@U…>`, `<#C…|name>`, `<!here>`, HTML entities) and cap at 200 chars.
- `OutlookSource.cs`: `OutlookAuth` is auth code + PKCE (S256) for a public client, no secret, scopes `offline_access User.Read Mail.Read`. The redirect is the bridge itself, `http://127.0.0.1:<bridge port>/integrations/outlook/callback`: the bridge listens on IPv4 loopback only, so `localhost` (which may resolve to `::1`) is not used; Entra matches `http://127.0.0.1` on any port for public clients. `OutlookSource` polls `GET /me/messages?$filter=isRead eq false` every 60 s (`OutlookPoll`), follows `@odata.nextLink` up to 500 items, and drops messages whose `parentFolderId` is Junk, Deleted Items or any folder under them. The folder map walks `mailFolders` and every `childFolders` level (paged, capped at 2000 folders) and is reloaded every 15 min. `where` is the folder display name ("Mail" for a folder not in the map). Access tokens stay in memory; a rotated refresh token is saved back to the vault (only while this source is still the running one, so an abandoned source cannot resurrect a disconnected account). Re-checks run one at a time (`_recheckGate`), so a focus re-check cannot race the poll. A 429 is retried up to 3 times after `Retry-After` (capped at 30 s, on the injected clock) without a new token grant; only a 401 forces one token refresh. `invalid_grant` becomes an error telling the user to connect again.
- `TokenVault.cs`: `ITokenVault` — `DpapiVault` (Windows, DPAPI CurrentUser over the vault file), `MacKeychainVault` (`security` generic passwords, service `codechroma`), `SecretToolVault` (Linux libsecret via `secret-tool`, secret on stdin), and `FileVault` — the 0600 fallback when `secret-tool` is missing or has no session, with a `Warning` shown in Settings. The file is `~/.codechroma/integration-tokens.json` (`UserPaths.IntegrationTokens`, `codechroma_INTEGRATION_TOKENS_FILE` overrides). Keys: `slack.user_token`, `slack.app_token`, `outlook.refresh_token`, `outlook.client_id` (own client only), `outlook.tenant` (non-default only). On macOS the write runs `security -i` with the command on stdin, so the secret never appears on argv, and reads the value back to confirm it.
- `MessagesService.cs`: hosted service that starts the saved sources with the bridge, validates and saves Slack tokens (`auth.test` + `apps.connections.open` must both succeed), runs the PKCE handshake (pending state in memory, 10 min, checked again on the callback), disconnects (stop + vault delete + feed clear) and throttles focus re-checks to one per 15 s. Connect, sign-in completion, disconnect and shutdown run one at a time per source (`Exclusive`), and `Start` cancels any runner it replaces, so overlapping requests cannot leave an orphaned loop. A runner is registered before its task starts, and state the task writes back (Slack identity, rotated Outlook refresh token) is dropped once it is no longer the current runner. Focus re-checks are tracked on their runner and awaited (with the loop, 5 s max) before a stop returns, so a disconnect cannot be refilled by a re-check still in flight. A failed Outlook callback is recorded as the source's error (unless a connection is still running), and starting a new sign-in clears it. `MessagesOptions` holds every endpoint, interval and the socket connector; tests swap the `HttpMessageHandler` and `SocketConnector`. `DefaultOutlookClientId` comes from `codechroma_OUTLOOK_CLIENT_ID`; ⚠ until the project registers its publisher-verified multi-tenant Entra app it is null and the user must enter their own client id.
- `slack-manifest.json` (embedded): the internal Slack app the user creates (user scopes `channels:read`, `groups:read`, `im:read`, `mpim:read`, `*:history`, `users:read`; user events `message.channels/groups/im/mpim`; Socket Mode on). The app-level token (`connections:write`) is created by hand under Basic Information.

### Routes (`Routes/MessageRoutes.cs`)

| Route | Body / answer |
|---|---|
| ⚠ every route below | refused with 403 unless the `Host` is loopback (`localhost`, `127.0.0.1`, `::1`), so a DNS-rebound page cannot read messages (`OriginGuard` only checks unsafe methods) |
| `GET /messages/unread` | `{sources: {slack, outlook: {state, error, synced_at}}, items: [{id, source, where, from, preview, at, open_url, web_url}]}`, newest first |
| `POST /messages/refresh` | focus re-check of every running source; `{started}` (false when throttled) |
| `GET /integrations` | `{slack: {connected, state, error, workspace, user}, outlook: {connected, state, error, account, client_id, tenant, default_client_available}, token_storage: {backend, warning}}` |
| `GET /integrations/slack/manifest` | the manifest JSON |
| `POST /integrations/slack` | `{user_token: "xoxp-…", app_token: "xapp-…"}` → `{workspace, user}`; 400 on a wrong prefix or a token Slack refuses (nothing saved) |
| `POST /integrations/outlook/connect` | `{client_id?, tenant?}` → `{auth_url}`; 400 when no client id is available |
| `GET /integrations/outlook/callback` | Entra redirect; exchanges the code and answers a small HTML page (400 for an unknown/expired state) |
| `DELETE /integrations/{slack\|outlook}` | stops the source, deletes its tokens, clears its items |

Tests: `dotnet/CodeChroma.Bridge.Tests/Messages/` (`MessageFakes.cs` fake Slack/Graph/login handler + scripted socket; `UnreadFeedTests`, `SlackSourceTests`, `OutlookSourceTests`, `MessageRoutesTests`, `TokenVaultTests`). `BridgeHost` registers a `MemoryVault`, so no test touches a real keychain.

## Web (`web/src/messages/`)

- `messagesClient.ts`: the wire types and fetchers (`bridgeRequest`).
- `messagesStore.ts`: one global `PanelStore` holding the feed (survives workspace switches); `useMessagesSync(client)` loads once, re-fetches on `EngineClient.subscribeMessages` (`messages-changed`, listed in `GLOBAL_EVENT_TYPES`), and on window focus calls `POST /messages/refresh` and re-fetches.
- `UnreadPanel.tsx`: `MessagesRailButton` (rail, under the terminal button; badge = item count, owns the sync) and `UnreadPanel` (absolute, right side of `.canvas-area`, clears the docked terminal via `--terminal-clearance`). The click goes through `messagesStore.activate`: while every source is `disconnected` it calls `settingsStore.open("integrations")` (`web/src/assistant/settingsStore.ts`, which holds Settings' open state and category so any control can deep-link into a category) and leaves the panel shut and the button unpressed; otherwise it toggles the panel. ⚠ The panel sits at z-index 45, above the agents dock (`.activity-panel`, 41) that shares the right edge; at a lower value it opens invisibly behind it. Per-source notes show "not connected" or the error; with nothing connected the panel offers a "Connect…" button that opens Integrations.
- `IntegrationsPanel.tsx`: Settings › Integrations (the rail button deep-links here while nothing is connected; Back returns to the Settings home). Reuses the Canvas style shell classes (`.canvas-style-dialog`, `-back`, `-lede`, `-warning`) and the agents' `.status-chip` (plus an `off` variant): a "No messenger is connected yet" notice while neither source is connected, then Slack and Outlook as two side-by-side cards (one column under 760 px) with a status pill each, so the whole dialog fits without scrolling. ⚠ `messages.css` loads before `styles.css`, so its overrides of shared classes use two-class selectors (`.agent-dialog.integrations-dialog`, `.integrations-dialog .integrations-warning`). Slack: steps, a "Copy manifest" link, the two token fields; Outlook: optional own client id (required when `default_client_available` is false) and tenant, Connect opens `auth_url` in the browser, re-reads `/integrations` (so an earlier failure's error state cannot end the new wait at once), and polls `/integrations` every 2 s until connected, the source reports an error (the failed callback), or 5 min pass (`OUTLOOK_WAIT_MS`); the last two show an error and re-enable Connect. Shows the token-storage warning.
- Tests: `UnreadPanel.test.tsx`, `IntegrationsPanel.test.tsx`.

Desktop shell: `CodeChroma.Shell/ExternalLinks.cs` lets `http`, `https` and `slack` links leave the WebView, both for top-level navigations (`NavigationStarting`) and for `window.open`/`target=_blank` (`WebViewNewWindowRequested`, which cancels the WebView load and hands only an allowed scheme to the OS), so the panel's `slack://` deep link reaches the Slack app and no other scheme does.
